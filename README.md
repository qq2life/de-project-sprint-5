# DWH: добавление нового источника и витрина по заказчикам

Учебный проект по интеграции нового источника данных в DWH маркетплейса товаров ручной работы и созданию инкрементальной витрины по заказчикам.

## Файлы

- `project.sql` — итоговый SQL-скрипт проекта.

## Что реализовано

1. Сбор данных из `source1`, `source2`, `source3` и нового источника `external_source`.
2. Обновление измерений:
   - `dwh.d_craftsman`;
   - `dwh.d_product`;
   - `dwh.d_customer`.
3. Обновление таблицы фактов `dwh.f_order`.
4. Создание витрины `dwh.customer_report_datamart`.
5. Создание таблицы дат загрузки `dwh.load_dates_customer_report_datamart`.
6. Инкрементальный перерасчёт витрины для изменившихся заказчиков и отчётных периодов.

## Гранулярность витрины

Одна строка витрины соответствует одному заказчику за один отчётный месяц (`customer_id + report_period`).

## Показатели витрины

- сумма покупок заказчика за месяц;
- доход платформы — 10% от суммы покупок;
- количество заказов;
- средняя стоимость заказа;
- медианное время выполнения заказа;
- самая популярная категория товаров;
- идентификатор самого популярного мастера;
- количество заказов в статусах `created`, `in progress`, `delivery`, `done`;
- количество незавершённых заказов;
- отчётный период в формате `YYYY-MM`.

Если несколько мастеров имеют одинаковое максимальное количество заказов у заказчика, выбирается один из них с помощью `ROW_NUMBER()`.

## Запуск

При первичном развёртывании выполняется `project.sql` целиком. DDL-блок создаёт витрину и таблицу контрольных дат.

При регулярном обновлении DDL-блок с `DROP TABLE / CREATE TABLE` повторно не выполняется. Запускаются:

1. сбор данных из источников;
2. обновление измерений и таблицы фактов;
3. инкрементальный блок обновления витрины.

## Контроль качества

В конце `project.sql` оставлены закомментированные проверочные запросы:

```sql
SELECT COUNT(*)
FROM dwh.customer_report_datamart;

SELECT
    customer_id,
    report_period,
    COUNT(*)
FROM dwh.customer_report_datamart
GROUP BY customer_id, report_period
HAVING COUNT(*) > 1;
```

При проверке проекта в рабочей БД витрина была успешно сформирована, повторный инкрементальный запуск не увеличил количество строк, а проверка на дубли по паре `customer_id + report_period` вернула 0 строк.
